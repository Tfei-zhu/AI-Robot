# Go 文章社区知识库

## 发布 Go 技术文章
1. 登录后点击“写文章”，填写标题、摘要、正文和至少一个标签；
2. 正文应说明适用的 Go 版本、运行环境和依赖，代码示例应可复制运行；
3. 提交后进入内容审核，审核通过即发布到社区。

## 文章标题与标签
1. 标题应准确描述问题和解决方案，避免“求助”“干货”等无信息标题；
2. 每篇文章可添加 1 至 5 个标签，推荐使用 Go、并发、网络、工程实践、标准库等技术标签；
3. 如涉及 Go 版本特性，请在标题或正文开头明确标注版本。

## Markdown 与代码块规范
1. 文章正文支持 Markdown；Go 代码请使用带 `go` 标识的 fenced code block；
2. 长代码示例应只保留解释所需的最小可运行片段，并说明预期输出；
3. 不要在代码或截图中公开 API Key、Token、数据库密码等敏感信息。

## 文章审核与修订
1. 新文章通常会进行自动和人工审核，审核通过后公开展示；
2. 审核不通过时请根据提示修改标题、内容或引用来源后重新提交；
3. 已发布文章可编辑，重大修订会在文章页保留修订记录。

## 引用、转载与版权
1. 引用文档、代码或图片时应标注原始来源和许可证；
2. 转载他人文章需取得授权，并在正文显著位置注明作者与原文链接；
3. 不得发布侵权内容、未经授权的付费资料或他人隐私信息。

## 评论与技术讨论
1. 评论应围绕文章的 Go 技术内容，鼓励补充依据、复现步骤或更优实现；
2. 对代码提出建议时请说明适用场景，避免仅给出结论；
3. 禁止人身攻击、广告引流、刷屏和与技术主题无关的内容。

## 收藏、关注与反馈
1. 在文章页可收藏文章、关注作者，并在个人中心查看收藏列表；
2. 发现错误可在评论区说明问题，或使用文章页的“反馈”入口提交勘误；
3. 文章数据（阅读、点赞、评论）可能有短暂延迟，以文章页显示为准。

## Go 示例质量要求
1. 示例应优先使用标准库；如使用第三方库，应注明模块路径和安装方式；
2. 并发示例需说明 goroutine 的退出方式、context 的传播和错误处理；
3. 性能结论应给出基准环境和可复现的 benchmark，避免将个例写成通用结论。
