数据审计发现：30 个故障条件只有 12 个不同公开需求，3 个公共任务族跨开发/留出。故障条件留出不能解释为任务泛化留出；这是固定脚本机制测试，不是有效的真实质量比较或独立总体样本。未来正式真实评测须用新的去重/分组任务重新冻结。本步没有看过留出后换数据来制造效果。

现有产品还有明确缺口：clarification_needed 仅有枚举，标准闭环没有可达返回路径。不可完成任务的拒绝失败不能全部归为模型能力；该产品改动应属于后续版本并重新冻结验证，不回改本轮被测实现。

已知限制保留：价格预占是配置上界估算而非账单，服务商异常超出预占则记实并封锁后续请求；没有真实 Token 返回，不能推算模型成本效益。SDK 注入使原 Go 报告 model_source 描述依赖注入来源，S8 的 mode/调用日志/版本元数据才标明评测传输类型；本轮均为 fixtures，live 未运行。固定脚本延迟主要是容器耗时，不能外推模型推理速度。Python 3.11、远程 CI、浏览器、本次真实外部业务服务未运行。
