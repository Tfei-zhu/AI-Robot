# AI-Robot 上下文管理改造计划书

版本：v1.0

日期：2026-10-14（Asia/Shanghai）
状态：方案已制定，业务代码尚未按本计划实施。

本项目通过统一模型输入预算、压缩工具结果、复用检索证据及增量历史摘要，改善长对话的约束保留能力，控制重复调用、耗时和成本。

---

## 一、目标与验收原则

### 1.1 本次目标

1. 将固定读取最近 6 轮升级为按 Token（模型计量文本长度的单位）预算选择历史。
2. 以结构化早期摘要补充被移出输入窗口的内容，保留目标、约束、纠正和未完成工作。
3. 在真正构造 ToolMessage（工具返回给模型的消息）时精简结果。
4. 对检索片段施加总预算，去除重复片段，复用有效的已有检索结果。
5. 通过长对话评测同时检查任务质量、上下文长度、重复调用、耗时及成本。

### 1.2 验收顺序

先检查任务完成和关键约束，再检查预算与消息协议，最后比较效率。输入缩短但任务质量出现可重复退化时，该阶段不通过。

本计划中的数值为初始配置或验收目标，实施后通过基线与真实模型实验校准，不作为已经取得的结果。

### 1.3 范围

覆盖普通 JSON 聊天、SSE（服务端持续推送事件）聊天、知识检索工具、文章工具，以及 Go 生成/修复路径的输入预算适配。增加原始会话、摘要及工具原文的保存能力，为追溯和补读提供依据。

跨会话用户画像、向量化个人长期记忆、自动进化、文档解析器更换、模型训练及跨进程任务队列单独规划。第一版生产部署仍以单应用进程为前提；进程内会话锁不能作为多进程串行化保证。

## 二、当前实现与差距

| 模块 | 当前行为 | 改造需求 |
| --- | --- | --- |

| app/rag/retriever.py | 控制片段数量；没有面向模型的总 Token 预算 | 在模型输入阶段控制证据体积、去重和复用 |

## 三、总体设计

### 3.1 调用链

认证账户与会话 → 读取已提交历史和摘要 → 构造本次状态 → 模型调用前计算完整预算 → 选择历史与证据 → 调用模型 → 工具执行或复用 → 保存原文并生成精简结果 → 再次构造模型输入 → 最终回答 → 提交会话与指标。

每次规划、最终生成、摘要生成都经过统一计量入口。普通响应与 SSE 使用同一个上下文构造器。

### 3.2 数据与视图分开

- 原始记录：已完成轮次、完整工具结果、证据来源和各次模型调用。
- 派生记录：摘要、约束条目、工具精简结果、检索复用索引。
- 模型输入视图：为当前调用临时选出的消息与证据。

LangGraph 的 add_messages 会合并消息。裁剪在模型调用前的临时视图中完成，避免通过返回短消息列表误以为已经覆盖图中旧消息。原始记录用于回溯，输入视图可以重建。

### 3.3 建议模块

| 建议新增文件 | 职责 |
| --- | --- |
| app/context/contracts.py | 预算、会话摘要、证据、工具投影和计量数据模型 |
| app/context/token_counter.py | 模型对应的 Token 计数及可信度标记 |
| app/context/budget.py | 计算完整输入、预留输出及预算分配 |
| app/context/builder.py | 为规划和最终回答构造消息视图 |
| app/context/tool_projection.py | 分类型精简工具结果 |
| app/context/evidence.py | 证据注册、去重、复用、补读与失效 |
| app/context/summary.py | 增量摘要、版本校验及失败处理 |
| app/context/store.py | SQLite（本地文件数据库）存储、账户隔离及事务 |
| app/context/usage.py | 模型调用次数、实际用量和成本估算 |

具体文件数量可在实施时调整，模块职责和阶段验收保持一致。

## 四、统一 Token 预算

### 4.1 计算范围

预算覆盖系统指令、工具定义、消息角色和工具调用结构、历史摘要、历史消息、当前问题、工具结果及检索证据。按最终序列化后的实际输入计算，不能只计算正文。

输入预算 = min(配置的输入上限，模型上下文窗口 − 本次输出预留 − 安全余量)。

初始建议：

| 配置 | 建议起点 | 说明 |
| --- | ---: | --- |
| 输入总上限 | 16,000 Token | 需与所选模型实际能力核对 |
| 普通回答输出预留 | 4,096 Token | 同步绑定实际生成参数 |
| Go 生成输出预留 | 8,192 Token | 保留当前代码生成路径的输出额度 |
| 安全余量 | 2,048 Token | 给协议开销和计量偏差留空间 |
| 历史摘要上限 | 1,000 Token | 约束清单与摘要合计计入此额度 |
| 近期历史上限 | 6,000 Token | 上限内优先完整保留最近轮次 |
| 检索证据总上限 | 4,000 Token | 当前输入视图中的去重证据总量 |
| 普通单工具结果上限 | 1,500 Token | 检索工具结果同时受证据总额度控制 |
| 单次补读上限 | 1,000 Token | 补读同样计入完整输入和工具轮次 |

分项额度不是独立可累加的授权；分配总量必须落在总输入上限内。未使用额度可以借给其他类别。当前需求、必要工具协议和系统指令先占实际空间。

### 4.2 计数器要求

1. 配置模型窗口大小、输出上限与对应 tokenizer（将文本编码为模型 Token 的工具）。
2. 工具定义、调用参数和消息封装纳入计量。
3. 发送前计数与服务商返回的实际用量分别记录，持续检查误差。
4. 不把字符数除以常数当作精确 Token 数。
5. 对没有验证过计数方式的模型，只允许观察模式；强制模式启动校验必须失败并明确原因，不能声称精确预算已生效。

### 4.3 选择与溢出策略

优先保留：系统规则与当前需求 → 用户明确约束与纠正 → 未完成工具调用和对应结果 → 当前任务必须证据 → 最近完整轮次 → 较早摘要及可选历史。

从可选历史、重复证据和低相关工具字段中回收空间。工具调用消息和全部对应结果作为一组处理，保留原始 tool_call_id（工具调用关联编号），避免孤立返回和未匹配调用。

必须内容本身已超预算时，返回可识别的 context_budget_exceeded 原因和需要缩减的内容类别；不静默截掉当前需求、硬性约束或关键源码。

预算检查必须发生在每一次实际模型调用之前，工具执行之后也要重新检查。

## 五、原始历史与增量摘要

### 5.1 保存模型

原始会话按认证主体和会话键保存，轮次编号单调增长。保存用户消息、最终回答、创建时间、run_id 和提交状态。摘要保存 version、covered_until_turn、来源轮次、生成模型、实际用量和校验结果。

成功完成一次请求后原子提交该轮消息；失败和取消不写入半条助手回答。重试以 run_id 防止重复提交。摘要覆盖范围只能包含已经提交的轮次。

第一版采用 SQLite 和锁保护，不因摘要生成而删除原始历史。存储期限和容量配置要写入文档；自动清理作为后续独立发布项，避免在本次迁移中引入历史删除。

### 5.2 摘要内容

| 字段 | 内容 |
| --- | --- |
| goal | 当前目标 |
| constraints | 明确要求、禁止事项及各自来源轮次 |
| corrections | 用户纠正、被替代的旧结论及生效范围 |
| confirmed_facts | 已确认事实，保留来源和不确定性 |
| decisions | 已确认的选择 |
| completed | 已完成事项 |
| pending | 未完成事项、阻塞条件 |
| evidence_refs | 必要证据和可补读编号 |

已过期约束和有效约束分开表示。不能把助手推测升级为用户要求，也不能把检索资料中的指令升级为系统规则。

### 5.3 触发与提交

- 当近期历史预计超出历史额度时，摘要尚未覆盖的较早轮次。
- 更新输入为上一版摘要与新增的已提交轮次，避免每轮重读全部历史。
- 采用触发和回落两个阈值，例如达到历史额度的 90% 时整理，整理到约 70%；具体值通过实验调整。
- 摘要更新按会话串行执行，使用版本比较后提交，防止旧任务覆盖新摘要。
- 失败时保持旧摘要和原始记录；能在预算内保留必要原文则继续，否则明确终止本次上下文构造。
- 摘要失败或未覆盖的历史不能被无提示丢弃。
- 每次摘要生成设时间和输出上限，最多一次应用层重试，所有尝试计入用量。

必须对约束来源、覆盖轮次、未知引用和输出长度进行确定性校验；摘要语义准确性通过真实模型长对话验收，不以结构合法代替语义正确。

### 5.4 缓存及旧路径兼容

原来的首轮语义缓存判断改用“该会话是否存在已提交轮次”，不能因历史全部被折叠成摘要而误判为首轮。缓存命中仍需写入完整会话轮次。

保留旧 MemoryStore 接口及最近 6 轮模式，便于对照与回退。启用新模式时，将进程内仍存在的历史幂等导入新存储；更早已经被删除的内容无法恢复，不虚构摘要。

## 六、工具结果精简与补读

### 6.1 精简规则

第一版优先使用字段选择、片段选择和结构化错误提取，减少额外模型压缩调用。

| 工具 | 必须保留 | 可以缩减 |
| --- | --- | --- |
| 知识检索 | 片段内容、标题、来源、证据编号、知识版本 | 重复片段、模型无须使用的检索耗时明细 |
| 文章查询 | 状态、文章 ID、用户所问字段、来源、查询时间 | 无关字段和重复说明 |
| 社区规范 | 与问题有关的规则、规则来源 | 重复引导语 |
| Go 验证 | 失败阶段、退出码、文件与位置、关键错误、截断标记 | 重复通过日志、无关测试事件 |

文章客户端需要保留结构化结果，不能只从已有自然语言回答中猜字段。通用未知工具使用保守投影，保留错误和来源，超过额度则提供补读入口。

### 6.2 原文与模型结果分离

完整工具结果保存到原文存储；真正进入 ToolMessage 的内容包含 status、result_id、必要数据、sources、truncated 和可补读范围。

新增受限的 read_tool_result 工具：只接受服务端签发的结果编号、字段或片段范围，不接受任意路径、SQL 或 URL；校验账户及会话归属。限定单次补读量，补读消耗原有工具轮次预算并单独计量。

截断不能产生非法 JSON、残缺必要代码或失去单位的数值。精简和补读均需保留来源映射。日志中记录哪些字段被省略，默认管理指标不展示用户原文。

## 七、检索预算、去重与复用

### 7.1 证据身份

每个证据记录 evidence_id、文档/片段 ID、内容摘要、标题路径、来源、知识版本、检索查询和相关度。不同来源的相同文本可以合并正文，但必须保留所有来源关系。

第一版以片段 ID 和内容摘要精确去重，不默认做语义近似合并，避免把内容相近但数值或否定条件不同的片段合并。

### 7.2 复用范围

1. 同一运行内：相同查询参数、过滤条件、账户权限和知识版本复用检索结果。
2. 同一会话跨轮：知识版本未变且复用时限内可复用，初始时限建议 10 分钟。
3. 启动实例编号与知识库 revision 一起构成当前有效版本，进程重启后的旧检索索引失效，避免 revision 重置导致误复用。
4. 查询规范化只做明确安全的处理；代码标识符大小写、否定词、数值和过滤条件保留。
5. 不跨账户、跨会话共享私有证据缓存。
6. 文章实时状态与 Go 实际验证结果不采用该检索缓存；更新后的信息必须重新查询或执行。

相似问题不直接视为同一查询。重复请求失败结果不永久缓存，可恢复故障仍按重试策略处理。

### 7.3 在模型输入中使用证据

- 对当前输入中的所有证据合计计量，按相关性、必要性及覆盖面选择。
- 新检索只增加新的必要片段，已有片段使用同一个证据编号。
- 模型输入构造器检查引用的证据是否实际可见；必要证据被裁掉时，重新放入或通过补读恢复。
- 仅出现“见 E1”而没有可见正文或可用读取入口，不算有效证据复用。
- 去重后不足以回答的需求允许补充检索；预算不足时明确说明信息缺口。
- 复用也算一次模型工具请求，不绕过现有工具轮次上限。记录 requested、executed、reused 三类次数。

## 八、Go 路径与接口兼容

普通聊天和 Go 任务共用预算与计量模块，采用不同的内容保留策略。

Go 路径必须保留固定接口、用户补充约束、服务端验收标准、必要上轮完整源码和关键报错。第一版只精简重复资料及冗余日志；必要源码放不下时明确返回预算失败，不能裁剪源码后仍要求模型保证完整修复。

保持当前最多三次生成调用及实际验证预算；摘要等额外模型调用必须单独设上限并计入总请求成本，不能借摘要名义绕开预算。本版 Go 任务不自动引入普通聊天历史。

保留已有 JSON 字段和 SSE 事件语义；新增 context_stats、token_usage、压缩/复用阶段事件为可选字段。取消后不提交半成品摘要和回答；Go 容器清理路径继续执行原有验收。

## 九、观测、Token 和成本口径

### 9.1 每次模型调用

记录 run_id、模型与调用阶段、尝试编号、输入估计、实际 input/output/total Token、缓存 Token 分类、用量来源、计数可信度、调用耗时及结果状态。规划、最终回答、摘要和重试分别记录。

服务商未返回用量时填 null，并标记估计值；不能按零消耗统计。SSE 输出事件计数保留为 stream_chunks，不能继续把事件数当 Token 数。若为兼容保留旧 tokens 字段，需要明确其旧口径。

被测路径统一使用应用层重试并关闭 SDK 隐式重试，逐次记账；所有对照组采用相同配置。失败请求是否实际收费无法确认时记录未知，不伪造账单。

### 9.2 每次任务

记录压缩前后输入估计、选取和省略轮次、摘要版本与覆盖范围、工具原文/投影体积、唯一证据数、去重数、检索 requested/executed/reused 次数、补读次数、整体耗时、首 Token 耗时及摘要额外耗时。

轨迹环形缓冲用于控制台，完整实验报告另行保存，避免超过 300 条后丢失评测数据。

### 9.3 成本

以服务商实际用量统计 Token；根据配置的模型单价及其版本估算金额，分别考虑输入、输出和缓存计费规则。模型单价未配置时仅报告 Token，不虚构金额。

总成本包含规划、最终生成、摘要、重试，以及检索/语义缓存涉及的 Embedding（文本向量化）调用。服务商账单可获得时另行核对；本地估算额不等于实际账单。

## 十、实施阶段与逐项完成清单

每阶段固定执行：开始前核对依赖和前一阶段结果 → 实现 → 单测/集成测试 → 记录文件与结果 → 达到门槛后进入下一阶段。失败则在本阶段修复；禁止把关键测试跳过视为阶段完成。

| 阶段 | 开始前验证 | 工作项 | 完成后测试与出口 |
| --- | --- | --- | --- |
| P0 基线与计量，约 1–2 日 | 记录工作区差异、模型配置、原测试结果；确认密钥可用性 | 建立固定任务集、用量字段、模型尝试计数和基线报告 | 原测试通过；流式事件和实际 Token 分开；无密钥时真实评测明确未运行 |
| P1 原始存储与预算基础，约 2 日 | P0 报告和计量可复现 | 原始会话/工具存储、版本提交、计数器、配置校验及观察模式 | 账户隔离、重启恢复、重复提交、取消、计数边界通过；生产消息输入尚不改变 |

| P5 增量早期摘要，约 2 日 | P4 裁剪行为稳定，原始历史可追溯 | 结构化摘要、约束/纠正来源、增量更新、失败回退及首轮缓存修正 | 早期约束和后续纠正保留；覆盖轮次连续；取消和摘要失败不损坏记录；D 组通过 |
| P6 Go 与控制台接入，约 1 日 | P5 普通问答和长对话通过 | Go 输入适配、上下文统计展示、配置/部署/回退文档 | Go 修复、来源、预算、取消清理回归通过；浏览器展示指标口径正确 |
| P7 综合验收与逐步启用，约 1–2 日 | P0–P6 记录齐全，质量集与评测集隔离 | 真实端到端评测、留出集验证、质量审核和发布报告 | 达到质量门槛后启用；否则明确记录失败、证据不足或待外部条件 |

单人参考工作量约 11–15 个工作日；模型接口不稳定、评测样本补充及缺少密钥的等待另计。阶段中的真实模型门槛缺少条件时标为待验收，可继续准备独立测试材料，不能宣称该阶段质量验证已完成。

## 十一、测试集和实验设计

### 11.1 四组实验

| 组别 | 方案 | 比较目的 |
| --- | --- | --- |
| A | 当前最近 6 轮和完整工具结果 | 当前基线 |
| B | 工具投影、检索预算、去重与复用 | 工具与证据管理的收益 |
| C | B + Token 历史选取 | 预算选择的影响 |
| D | C + 增量早期摘要 | 摘要是否恢复早期信息 |

固定同一模型、采样参数、最大输出、知识快照、工具数据和重试规则。切换实验策略版本时隔离答案缓存，主实验关闭最终答案语义缓存，单独测试缓存兼容性，避免缓存命中掩盖上下文质量。

### 11.2 样本

建议建立 30 条对话脚本，其中 20 条用于调参与开发，10 条作为独立留出集；覆盖约 10、30、60 轮三种长度，具体分布在数据集文件中固定。

至少覆盖：

1. 早期声明“只用标准库”，后期仍需要生成代码。
2. 用户后续纠正 Go 版本、函数签名或处理策略。
3. 插入大量无关话题后恢复原任务。
4. 相同检索请求、多轮重复片段及跨轮复用。
5. 问题相似但关键数值、否定词或实体不同，需要新检索。
6. 长文章、长表格、长报错，关键信息位于尾部。
7. 知识库更新后必须读取新证据，实时文章数据不得误复用。
8. 连续工具调用、多个工具并行结果及补读。
9. 摘要失败、计量不可用、预算溢出和客户端取消。
10. 不同账户相同会话编号、同账户不同会话、重启恢复。
11. Go 场景失败后修复，关键接口和验收测试要求持续有效。

每条脚本包含目标、有效约束、纠正生效轮次、允许工具、预期必需证据和可执行或人工核验的终局标准。

### 11.3 两层评测

- 离线确定性测试：固定模型和工具输出，验证计数、裁剪、去重、协议、存储及失败路径；不能用于宣称真实任务完成率。
- 真实模型测试：先做少量快照和短链路筛选，再对 A/B/C/D 运行端到端长对话；各组独立生成全部助手回复，不用预设正确回答代替中间输出。

每条真实任务建议至少重复 3 次并配对比较；固定可控制的参数，记录模型不支持 seed（随机种子）等情况。开发阶段可只筛选有改动的组，最终保留四组完整报告。

先计算预期调用规模，设置评测调用数、Token 和金额上限；达到上限暂停实验并记录已完成样本，不把未运行样本填成成功。真实评测需要本地模型密钥；金额上限依赖明确配置的单价。

## 十二、指标与验收门槛

| 指标 | 定义 | 建议门槛/目标 |
| --- | --- | --- |
| 任务完成率 | 满足终局验收条件的任务数 / 已执行任务数 | 相对 A 不出现可重复、未解释的退化；最终配对差值 95% 置信区间下界建议不低于 −3 个百分点 |
| 关键约束保留率 | 最终行为满足的仍有效关键约束数 / 应满足数 | 固定硬约束用例 100%；不能只检查摘要是否提到约束 |
| 普通约束保留率 | 满足的普通约束数 / 应满足数 | 初始目标至少 98%，按真实基线校准 |
| 重复工具请求 | 模型再次提出且没有新增信息需求的调用次数 | 相比 A 不增加，独立报告，不能用缓存命中掩盖模型循环 |
| 冗余后端执行 | 相同有效缓存键下重复实际执行的检索次数 | 确定性复用用例为 0；实时查询与更新失效不算冗余 |
| 输入长度 | 每次实际调用及整个任务的输入 Token | 强制模式估计输入 100% 符合预算；实际用量偏差超限必须调查 |
| 输入节省 | 指定长上下文样本相对 A 的总输入减少比例 | 目标至少 20%；其他样本如实报告，不能只挑有利结果 |
| 耗时 | 端到端 P50/P95、首 Token 及摘要额外耗时 | 初始目标整体 P95 不增加超过 10%，摘要触发组单独报告 |
| 成本 | 每完成任务的实际 Token 与金额估算 | 包含摘要/重试/Embedding 后，目标不高于 A |
| 协议与隔离 | 工具消息配对、来源可读及账户隔离 | 全部确定性测试通过，跨账户泄漏为 0 |

小样本可能无法证明统计上的非劣性（质量下降不超过允许范围）；置信区间不满足时标记证据不足并补样本，不能因为平均值更高就宣称完成质量验收。硬约束失败必须定位修复，不能由总体平均值抵消。

达不到效率目标时记录该目标未达成；质量上升但成本增加的结果单列，不能声称全面优化。

## 十三、配置、启用和回退

建议新增配置类别：

- CONTEXT_MODE：off / observe / enforce。
- 模型窗口、输入上限、输出预留、安全余量与 tokenizer 配置。
- 历史、摘要、证据、工具结果及补读额度。
- 摘要触发阈值、超时和调用上限。
- 证据复用时限、原文存储位置与实验策略版本。
- 实际用量采集和可选单价配置。

off 使用原来的最近 6 轮路径。observe 只进行确定性候选构造与计量，不改变实际发送内容，也不偷偷增加摘要模型调用。enforce 使用通过验收的新输入视图；若缺少可信计数配置则拒绝开启。

按 off 基线 → observe → 测试账户 enforce → 扩大启用范围推进。配置切换与策略版本写入报告。共享答案缓存按策略版本隔离。

出现硬约束回归、无依据摘要、错误证据复用、消息协议错误、未解释的成本/延迟增加时，停止扩大范围并回退 off。原始会话、工具结果和评测记录保留，摘要版本保留供定位；回退继续使用最近 6 轮原文，不读取不合格摘要。

## 十四、交付物与完成定义

1. 上下文预算、消息视图、工具投影、证据复用、摘要及持久化模块。

完成定义：功能与回归测试通过、真实质量门槛得到足够证据、关键约束无回归、成本与延迟口径完整、失败可追溯且回退路径可用。未运行真实模型、只有固定输出或平均输入变短，都不能单独作为最终完成依据。
